## Goal and outcome
- Goal: Replace the flat project task/plan sidebar with a true tiered orchestration tree driven by the hierarchy endpoint.
- Outcome: Added a hierarchy-based tree UI to Project Detail that renders tier/status/blocking/dependency context, supports node expand/collapse, preserves sidebar collapse behavior, and routes node selection to the correct detail page.

## Key code changes
- Added `web/src/components/OrchestrationTree.tsx`:
  - New recursive tree component consuming hierarchy roots (with row-based fallback tree construction).
  - Renders tier badges for `epoch|phase|plan|task|exec`.
  - Renders lifecycle status badges, blocked state badge, and dependency indicators.
  - Supports per-node expand/collapse state and auto-expands loaded roots.
  - Provides keyboard-safe left/right arrow handling for expand/collapse on focused node links.
  - Includes collapsed sidebar mode with hide/show controls matching existing UX.
- Updated `web/src/pages/ProjectDetailPage.tsx`:
  - Replaced `TaskSidebar` usage on this page with `OrchestrationTree`.
  - Added `hierarchyRoots` state and wired hierarchy response roots/nodes from `getHierarchy(projectId)`.
  - Added `hierarchyRows` memo fallback derived from tasks when hierarchy is unavailable.
  - Kept existing node creation flow, tabs, and IDE pane intact.
- `web/src/components/TaskSidebar.tsx`:
  - No code changes required for this task; integration moved to `OrchestrationTree` in `ProjectDetailPage`.

## Tests/validation performed
- Ran web build/typecheck and production bundle:
  - `npm run build -w web`
- Result:
  - TypeScript build succeeded.
  - Vite production build succeeded.
  - Existing bundle-size warning remains (pre-existing, non-blocking for this task).

## Remaining risks or follow-ups
- Tree keyboard support currently focuses on expand/collapse only; full ARIA tree semantics (roles, roving tabindex, home/end navigation) are not yet implemented.
- Selection highlight is supported via `selectedNodeId` prop but currently not wired from route state on `ProjectDetailPage`.
- Fallback hierarchy reconstruction relies on `parentPlanTaskId`, so it may not represent all tier relationships if backend hierarchy data is unavailable.
- `web/tsconfig.tsbuildinfo` changed as part of build output; decide whether to keep or ignore this artifact in version control policy.
