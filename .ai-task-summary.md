## Goal and outcome
- Goal: Extend frontend API typing and client request helpers so orchestration endpoints can be consumed with explicit TypeScript contracts.
- Outcome: Added typed orchestration models and typed client helpers for unified node creation, hierarchy retrieval, dependency graph retrieval, node detail retrieval, and node action mutations. Web build passes after changes.

## Key code changes
- Updated `web/src/api/types.ts` with explicit orchestration types:
  - Added tier union: `NodeTier = "epoch" | "phase" | "plan" | "task" | "exec"`.
  - Added create-node models: `CreateNodePayload`, `CreateNodeResponse`, plus dependency ref type.
  - Added hierarchy models: `ProjectHierarchy`, `HierarchyNode`, `HierarchyNodeRow`, `GetHierarchyResponse`.
  - Added dependency graph models: `ProjectDependencyGraph`, `DependencyGraphNode`, `DependencyGraphEdge`, `GetDependencyGraphResponse`.
  - Added node detail/action models: `OrchestrationNodeDetail`, `StartNodePayload/Result`, `SetNodeAutoModePayload`, `SetNodeAutoMergePayload`, `ForceReReviewPayload`, `ApproveBudgetOverridePayload`, `NodeMutationResult`, `AsyncNodeActionResult`.
- Updated `web/src/api/client.ts` with typed helpers:
  - `createNode(projectId, payload)`
  - `getHierarchy(projectId)`
  - `getDependencyGraph(projectId)`
  - `getNode(nodeId)`
  - `startNode(nodeId, payload?)`
  - `setNodeAutoMode(nodeId, payload)`
  - `setNodeAutoMerge(nodeId, payload)`
  - `forceNodeReReview(nodeId, payload?)`
  - `approveNodeBudgetOverride(nodeId, payload?)`

## Tests/validation performed
- Ran web build/typecheck:
  - `npm run build -w web`
- Result:
  - TypeScript compile succeeded.
  - Vite production build succeeded.

## Remaining risks or follow-ups
- `OrchestrationNodeDetail` currently keeps some server payload sections (`dependencyDiagnostics`, `waiting`, `automation`, `orchestration`) as `unknown`; these can be tightened with richer explicit types in a follow-up.
- Existing page components still use direct `api(...)` calls for many non-orchestration endpoints; a broader client-helper migration could further reduce inline request typing.
- If strict “no any-based calls” is required across broader UI pages, additional cleanup of `catch (error: any)` patterns in page files is still pending.
