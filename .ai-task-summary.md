Goal and outcome
- Goal: Before parent auto-merge/finalization, surface deterministic completion evidence so users can inspect synthesis summary, requirement-to-evidence coverage, verification verdicts, and delta-loop history.
- Outcome: Completion artifacts are now persisted in node metadata, exposed via task/plan APIs in a normalized `completion` object, and rendered in the Task Detail UI with clear requirement->evidence mapping and unresolved gap visibility.

Key code changes
- Completion artifact persistence and enrichment:
  - `server/src/services/orchestration/completion.ts`
  - Extended synthesis evidence rows with `repo_path`, `module_ref`, and `test_ref` extracted from child outputs.
  - Persisted artifact snapshots in metadata under `custom.completion_artifacts`:
    - `synthesis`
    - `verification`
    - `delta_loop_history` (capped to latest 20 entries)
  - Continued storing linkage fields:
    - `synthesis_artifact_event_id`
    - `verification_artifact_event_id`
    - `verification_verdict`

- API exposure for tasks/plans:
  - `server/src/routes/tasks.ts`
  - `server/src/routes/plans.ts`
  - Added `completion` to serialized task payloads with:
    - artifact event ids
    - verification verdict
    - summary shortcut
    - synthesis artifact
    - verification artifact
    - delta loop history
  - Added event-payload fallback when metadata snapshots are unavailable (backward compatibility with older records).

- Frontend types and rendering:
  - `web/src/api/types.ts`
  - Added completion artifact/coverage/history type models.
  - `web/src/pages/TaskDetailPage.tsx`
  - Completion Summary now prefers synthesized summary.
  - Added “Completion Evidence” section rendering requirement->evidence coverage matrix.
  - Added “Verification Outcome” section showing verdict, reasons, and failing requirements.
  - Added “Gap Closure History” section showing verification iterations and delta-plan/budget signals.

- Documentation:
  - `docs/architecture/completion-evidence.md`
  - Documented artifact lifecycle, metadata contracts, API exposure, and UI behavior.

Remaining risks or follow-ups
- Evidence extraction for `repo_path`/`module_ref`/`test_ref` uses deterministic heuristics; richer semantic extraction may improve precision.
- `completion` builder logic is duplicated in both `tasks` and `plans` routes; consider refactoring to a shared service to reduce drift risk.
- No dedicated new integration assertions were added specifically for API `completion` payload shape and UI rendering branches; adding focused coverage would reduce regression risk.
- UI currently displays artifact references as text; deep-linking to task details, files, or test artifacts could improve investigation workflow.
