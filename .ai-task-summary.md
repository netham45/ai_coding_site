# Task Summary

## Goal and outcome
- Goal: Ensure decomposition jobs use intended tier decomposition prompts (`epoch->phases`, `phase->plans`, `plan->subplans/tasks`, `task->exec tasks`) and are not routed through execution-only templates.
- Outcome: Completed. Decompose prompt routing was corrected so task-tier decomposition no longer uses `task-execution.md`; regression tests were added to lock routing behavior.

## Key code changes
- Corrected decomposition prompt mapping:
  - File: `server/src/services/orchestration/promptRuntime.ts`
  - Updated `decompositionTemplateByTier`:
    - `task` from `prompts/task-execution.md` -> `prompts/task-to-exec-tasks.md`
    - `exec` from `prompts/exec-task-runner.md` -> `prompts/task-to-exec-tasks.md`
- Added regression tests for prompt selection:
  - File: `server/src/services/orchestration/promptRuntime.test.ts`
  - New coverage verifies:
    - Decompose jobs select the expected decomposition template for each tier.
    - Non-decompose jobs (`evaluate_readiness`, `synthesize`, `verify`) still resolve to shared orchestration templates.

## Research performed for this task and key findings
- Inspected prompt artifacts under `prompts/` to confirm intended decomposition templates exist for all tiers.
  - Key finding: Correct decomposition templates are present (`epoch-to-phases`, `phase-to-plans`, `plan-to-subplans-and-tasks`, `task-to-exec-tasks`).
- Traced prompt-selection call path in orchestration runtime.
  - Key finding: `server/src/services/orchestration/promptRuntime.ts` routed `task` decompose jobs to `task-execution.md`, which is execution-oriented and not decomposition-oriented.
- Reviewed decompose job wiring in `server/src/services/orchestration/jobs/decompose.ts`.
  - Key finding: Job orchestration itself was not the source of the mismatch; template selection map was the issue.

## Questions answered during this task, including each answer
- Question: Where is decomposition prompt routing decided?
  - Answer: `selectPromptTemplateByTier(...)` in `server/src/services/orchestration/promptRuntime.ts`.
- Question: Was task-tier decomposition incorrectly using an execution-only prompt?
  - Answer: Yes. It was mapped to `prompts/task-execution.md`.
- Question: Which prompt should task-tier decomposition use?
  - Answer: `prompts/task-to-exec-tasks.md`.
- Question: Should non-decompose orchestration jobs be changed?
  - Answer: No. They should continue using `readiness-evaluation.md`, `synthesis.md`, and `verification.md` respectively.

## Remaining risks or follow-ups
- Current decompose worker behavior does not yet materialize children directly in `runDecomposeForTask`; this change strictly corrects template routing selection and adds test coverage around it.
- `exec` tier is mapped to `task-to-exec-tasks.md` for decompose jobs to keep decomposition off execution-only templates. If product semantics later require no decompose template for `exec`, that policy should be made explicit in orchestration rules and tests.
- If there are external consumers relying on previous prompt-path expectations for `task` decompose jobs, they should be checked for compatibility.
