# Task Summary

## Goal and outcome
- Goal: Add `ready_merge` and `merge` commands for both task and plan entities, enforce state-transition/precondition rules, perform atomic persistence updates, and return clear final status summaries.
- Outcome: Completed. CLI and application services now support both entities, with transition guards, transactional merge record/task updates, and summary-oriented command output.

## Key code changes
- Added merge-ready/merge support for plan entities in application services:
  - `markPlanMergeReady({ userId, planId })`
  - `mergePlan({ userId, planId })`
- Enforced merge-ready transition guard for task and plan entities:
  - Allowed statuses: `in_progress`, `waiting_input`, `merge_conflict`, `merge_ready`
- Added plan-specific precondition checks:
  - Prevent marking/merging a plan when child tasks under `parent_plan_task_id` are not all `merged`
- Ensured merge persistence updates are atomic:
  - Transactional updates for merge result + task status + state transition
  - Retained merge record lifecycle (`pending` -> `merged|conflict|failed`)
- Corrected task merge service DB intent from read to write:
  - `mergeTask` now resolves task with write intent
- Added final status/result summaries in service responses:
  - `summary` fields for `ready_merge` and `merge` flows
- Updated CLI command handling and help text:
  - Added entity-aware syntax:
    - `ready_merge task <taskId>`
    - `ready_merge plan <planId>`
    - `merge task <taskId>`
    - `merge plan <planId>`
  - Kept backward compatibility aliases:
    - `ready_merge <taskId>`
    - `merge <taskId>`
  - Non-JSON output now prints `summary` when available
