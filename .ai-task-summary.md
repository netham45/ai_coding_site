# Task Summary

## Goal and outcome
- Goal: Audit current behavior against the target flow: non-exec node start should trigger AI runtime session, runtime should write YAML, users should explicitly run extract/approve before materializing children, and deterministic mirrored child auto-creation should not occur.
- Outcome: Audit completed. Current implementation diverges from target in multiple places and those findings are captured below.

## Findings (expected vs current)
- Non-exec node start -> AI runtime session:
  - Expected: starting a non-exec node should launch runtime.
  - Current: behavior is split. `tasks start` / `session start` call runtime for any mode, but `/nodes/:nodeId/start` routes non-exec tiers to orchestration `decompose` instead of runtime.
  - Refs: `src/cli/index.ts:376`, `src/application/cliServices.ts:1367`, `src/routes/tasks.ts:1306`, `src/routes/tasks.ts:1344`.
- Runtime writes YAML artifact:
  - Expected: plan runtime writes `.ai-plan/latest-plan.yaml`.
  - Current: implemented by prompt contract; extraction reads file first (with session output fallback).
  - Refs: `src/application/cliServices.ts:793`, `src/application/cliServices.ts:696`, `src/application/cliServices.ts:2156`.
- User explicitly extracts/approves before child materialization:
  - Expected: children materialize only after explicit `plans extract` + `plans approve`.
  - Current: regressed; orchestration worker auto-extracts and auto-approves eligible plan output.
  - Refs: `src/services/planOrchestrator.ts:223`, `src/services/planOrchestrator.ts:257`, `src/index.ts:33`, `src/integration.test.ts:1969`.
- No deterministic mirrored child auto-creation:
  - Expected: no deterministic automatic child creation.
  - Current: regressed; decomposition and delta-plan jobs create deterministic child IDs and auto-create children.
  - Refs: `src/services/orchestration/jobs/decompose.ts:41`, `src/services/orchestration/jobs/decompose.ts:129`, `src/services/orchestration/jobs/deltaPlan.ts:40`, `src/integration.test.ts:2652`.
