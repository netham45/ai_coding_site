## Goal and outcome
- Goal: Introduce one explicit backend create endpoint the UI can call for all top-level user tiers (`epoch`, `phase`, `plan`, `task`) while preserving existing storage primitives and dependency validation.
- Outcome: Added `POST /api/projects/:projectId/nodes` that supports all four tiers, maps tiers to existing `tasks` storage conventions, reuses orchestration dependency validation and workspace setup behavior, and returns serialized node payloads compatible with current task serialization.

## Key code changes
- Added unified node creation request validation in `server/src/routes/tasks.ts` via `createNodeSchema`.
- Implemented new route `POST /api/projects/:projectId/nodes` in `server/src/routes/tasks.ts`:
  - Accepts `title`, `taskPrompt`, `nodeTier`, optional `aiCommand`, optional `parentNodeId`, dependency refs/ids, and automation flags.
  - Maps creation conventions:
    - `epoch|phase|plan` -> task row `mode='plan'` and metadata tier set to requested tier.
    - `task` -> task row `mode='execution'` and metadata tier `task`.
  - Reuses existing workspace and branch initialization logic (`cloneLocalBaseToWorkspace`, `createTaskBranch`, `getHeadCommitSha`) and derives source repo/branch from parent node when provided.
  - Reuses orchestration dependency validation (`resolveAndValidateNodeDependencies`) and dependency partitioning (`partitionDependenciesByTier`), persists `task_dependencies`, and sets blocked state semantics.
  - Reuses metadata construction and serialization (`buildInitialNodeMetadata`, `serializeNodeMetadata`) and existing serializer response shape (`serializeTask`).
- Added `UserNodeTier` type alias in `server/src/types.ts` for the user-facing tier set.
- Added integration coverage in `server/src/integration.test.ts`:
  - New test creates `epoch`, `phase`, `plan`, and `task` through the unified endpoint.
  - Verifies persisted mode/tier mapping and dependency persistence.

## Remaining risks or follow-ups
- New endpoint currently mirrors task prompt handling for plan-like tiers; if UI expects planner-format injection for direct `plan` tier creation, a follow-up may be needed to align prompt shaping behavior.
- Event payload for node creation reuses existing `task.created`/`plan.created` event families; downstream consumers should confirm they handle the new `nodeTier` field consistently.
- Frontend/UI integration work is still required to call this endpoint for tiered node creation and to handle feature-flag-disabled orchestration endpoint responses where applicable.
