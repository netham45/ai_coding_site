# Task Summary

## Goal and outcome
- Goal: update `server/src/routes/projects.ts` so project list/membership/global metadata stays in app DB while prompt/config fields are read/written from each project DB, and ensure auth checks against `project_members` happen before any project DB access.
- Outcome: completed. Project routes now perform membership checks and project metadata lookup from app DB first, then hydrate prompt/config from project-local config only where needed. Serialization and shared server types were aligned to reflect app metadata vs project config ownership.

## Key code changes
- Updated `server/src/types.ts`:
  - Introduced `AppProjectRow` for app DB project metadata fields.
  - Introduced `ProjectConfigFields` for project-local config fields.
  - Kept `ProjectRow` as a composed type: `AppProjectRow & ProjectConfigFields`.
- Updated `server/src/routes/projects.ts`:
  - Switched imports to use new `AppProjectRow`/`ProjectConfigFields` types.
  - Replaced prior mixed helper with two explicit helpers:
    - `appProjectForUser(...)` for auth + metadata lookup from app DB (`projects` + `project_members`).
    - `hydratedProjectForUser(...)` for app DB lookup followed by project DB config hydration.
  - Kept config hydration in `projectConfigFor(...)` via `getProjectConfig(...)` (project DB source of truth).
  - Ensured project DB access only occurs after auth-gated app lookup.
  - Updated `PATCH /api/projects/:projectId`:
    - Name update remains in app DB.
    - Config updates read current project-local config (when needed) and write via `upsertProjectConfig(...)`.
  - Updated routes that do not require prompt/config to use app DB metadata only (no project DB touch):
    - `GET /:projectId/files`
    - `POST /:projectId/ide/start`
    - `POST /:projectId/ide/stop`
    - `GET /:projectId/ide/view`
    - `ALL /:projectId/ide/proxy*`
  - Updated create response lookup to use `appProjectForUser(...)` before hydration.

## Tests/validation performed
- Ran `npm run build -w server`.
- Result: successful TypeScript compilation (`tsc -p tsconfig.json`) with no errors.

## Remaining risks or follow-ups
- `server/src/routes/tasks.ts`, `server/src/routes/plans.ts`, and `server/src/services/runtime.ts` still use `ProjectRow` selections directly from app DB in places; those paths may need equivalent metadata/config split handling to avoid relying on legacy config columns.
- No dedicated automated tests were added for:
  - auth-before-project-DB-access behavior,
  - list/get/patch serialization sourcing config strictly from project DB,
  - app-only route behavior (files/IDE endpoints) under missing/corrupt project DB conditions.
- Integration-level checks for end-to-end consistency (create project -> update config -> task prompt generation) would reduce regression risk.
