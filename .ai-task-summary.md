# Task Summary

## Goal and outcome
Goal: Implement the app-vs-project SQLite ownership split defined in `docs/adr-sqlite-persistence-split.md`.
Outcome: Completed. Global entities are persisted in `data/app.sqlite`; project-local entities are persisted in `<project.base_path>/.ai-coding/project.sqlite`.

## Key code changes
- Split schema ownership in `server/src/db/migrations.ts`:
  - App DB: `users`, `user_settings`, `projects`, `project_members`
  - Project DB: `tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`, plus `project_metadata` and `project_config`
- Refactored DB layer in `server/src/db/index.ts`:
  - Added `appDb`
  - Added per-project DB open/init/cache/validation helpers
  - Added metadata validation and project-config ownership in project DB
  - Added explicit invariants comments: single source of truth per table, no cross-file foreign keys, cross-DB linkage by IDs only
- Added `server/src/db/ownership.ts` for project/task context resolution.
- Rewired routes/services/websocket gateways to enforce app DB vs project DB ownership boundaries.
- Updated `server/src/types.ts` and `README.md` for the split persistence model.

## Tests/validation performed
- `npm run build -w server` passed.
- `npm run build` (server + web) passed.

## Remaining risks or follow-ups
- Historical migration from monolithic runtime/task data into per-project DB files is not included in this task.
- Some cross-project task lookups are scan-based and may need optimization at larger scale.
- Operator tooling for project DB repair/recovery can be expanded.
