# Task Summary

## Goal and outcome
- Goal: fix rerun failures caused by `NOT NULL constraint failed: tasks.base_commit_sha_at_create`.
- Outcome: rerunning a task now preserves the schema constraint by setting `base_commit_sha_at_create` to a valid source commit SHA instead of `NULL`.

## Key code changes
- Updated rerun logic in `server/src/routes/tasks.ts` (`POST /tasks/:taskId/rerun`):
  - Determine rerun source path:
    - default: `project.base_path`
    - if plan child task: parent plan task workspace path
  - Compute `baseCommitSha` using `getHeadCommitSha(sourcePath)`.
  - Update task reset SQL to write `base_commit_sha_at_create = ?` with `baseCommitSha` (previously set to `NULL`).

- Added regression coverage in `server/src/integration.test.ts`:
  - Added helper `gitHead(cwd)`.
  - New test: `task rerun resets task without violating base commit NOT NULL constraint`.
  - Test creates a repo with two commits, inserts a failed task with the first SHA, reruns the task, and verifies:
    - API returns success
    - `baseCommitShaAtCreate` equals latest repo HEAD
    - DB row status is `queued` and `base_commit_sha_at_create` is non-null/latest SHA.

## Tests/validation performed
- Ran full server integration tests:
  - `cd server && npm test -- --runInBand`
- Result: all tests passed (`26` tests, `0` failures).

## Remaining risks or follow-ups
- Current regression test covers execution-mode tasks rerun from project base repo; consider adding a dedicated test for plan-child tasks rerun from parent plan workspace to validate source-path selection in that branch.
- If repository state is unavailable/corrupt at rerun time, endpoint behavior still returns conflict/error as designed; no additional retry strategy was introduced.
