# Task Summary

## Goal and Outcome
- Goal: Replace the single default AI command setting with support for multiple commands, and change task creation so AI command is selected from a dropdown with `Other` as the final option for manual override.
- Outcome: Completed. Settings now persists an ordered list of default AI commands, and the Create Task form now uses a dropdown sourced from settings with an `Other` override input.

## Key Code Changes
- Backend settings schema/storage updated for multi-command support:
  - Added `default_ai_commands` column to `user_settings` migration with JSON default.
  - Added legacy migration/backfill logic to ensure existing rows get a valid `default_ai_commands` value.
  - Files:
    - `server/src/db/migrations.ts`
    - `server/src/db/appDb.ts`

- Backend API/types updated:
  - `UserSettingsRow` now includes `default_ai_commands`.
  - Settings API now:
    - accepts `defaultAiCommands: string[]` (and still accepts legacy `defaultAiCommand`),
    - normalizes/trims/deduplicates commands,
    - returns both `defaultAiCommands` and `defaultAiCommand` (first item).
  - Files:
    - `server/src/types.ts`
    - `server/src/routes/settings.ts`

- Runtime default AI command resolution updated:
  - Task/plan command fallback now prefers first entry from `default_ai_commands`, with safe fallback to legacy `default_ai_command`.
  - Files:
    - `server/src/routes/tasks.ts`
    - `server/src/routes/plans.ts`

- Frontend settings page updated for multiple commands:
  - Replaced single command input with dynamic multi-row command editor (+ / - controls).
  - Saves via `defaultAiCommands` array.
  - Files:
    - `web/src/pages/SettingsPage.tsx`
    - `web/src/api/types.ts`

- Frontend task creation updated to dropdown + Other override:
  - Loads user settings commands and renders dropdown.
  - Adds `Other` as final option.
  - Shows custom command input only when `Other` is selected.
  - Uses selected/override value in task create payload.
  - File:
    - `web/src/pages/ProjectDetailPage.tsx`

## Remaining Risks or Follow-ups
- Data shape risk:
  - `default_ai_commands` is stored as JSON text. Corrupt/manual edits are handled with fallback logic, but a DB-level JSON constraint is not enforced.

- UX follow-up:
  - Create Plan still uses a free-text AI command input. If desired, it can be aligned to the same dropdown + `Other` behavior for consistency.

- Validation follow-up:
  - No dedicated new integration test was added for the settings API multi-command behavior yet; current verification relies on build/tests and manual flow logic.
