## Goal and outcome
- Goal: Expose node-level orchestration operations in the existing task/plan detail UX so users can operate orchestration flows directly in the web UI.
- Outcome: Added node orchestration detail loading and a dedicated UI panel for lineage, blocking diagnostics, unresolved dependency reasons, and orchestration actions. Actions now execute against `/api/nodes/:nodeId/*` endpoints and refresh detail state after success.

## Key code changes
- Added [web/src/components/NodeActionsPanel.tsx](web/src/components/NodeActionsPanel.tsx):
  - Renders node tier + mode, parent and children overview.
  - Parses and displays waiting/blocking diagnostics and unresolved dependency reason details from node APIs.
  - Adds orchestration controls for:
    - Start node (`/api/nodes/:nodeId/start`)
    - Auto-mode toggle (`/api/nodes/:nodeId/auto-mode`)
    - Auto-merge toggle (`/api/nodes/:nodeId/auto-merge`)
    - Force re-review (`/api/nodes/:nodeId/force-re-review`)
    - Budget override approval (`/api/nodes/:nodeId/approve-budget-override`)
- Updated [web/src/pages/TaskDetailPage.tsx](web/src/pages/TaskDetailPage.tsx):
  - Imports typed orchestration client helpers and `NodeActionsPanel`.
  - Adds node detail state (`nodeDetail`, loading/error state, node action loading state).
  - Adds `loadNodeDetails` using `getNode(entityId)`.
  - Loads node details on entity change and alongside existing polling.
  - Adds shared node action executor that calls endpoint helpers, shows toast feedback, and refreshes both task detail + node detail state.
  - Integrates `NodeActionsPanel` in Task Info view.

## Tests/validation performed
- Ran `npm run build -w web`:
  - TypeScript project build succeeded.
  - Vite production build succeeded.
- Ran `npm run cli -- --help` from `server/` per prompt constraints:
  - CLI command and help output succeeded.

## Remaining risks or follow-ups
- Node detail payload sections (`waiting`, `dependencyDiagnostics`, `orchestration`, `automation`) are still typed as `unknown` at API type level and are parsed defensively in UI; stronger explicit frontend types would reduce runtime parsing logic.
- The page now polls both task and node endpoints every 3 seconds; if endpoint volume becomes a concern, polling cadence or conditional refresh triggers may need tuning.
- `web/tsconfig.tsbuildinfo` is updated as a build artifact; repository policy should decide whether to track or ignore it.
