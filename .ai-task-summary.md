## Goal and outcome
- Goal: Implement `re_review(node)` and `delta_plan(parent)` orchestration jobs with intelligent unblocking, dedupe/debounce anti-thrash controls, bounded replanning budgets (default `3`), and an explicit user override requirement to exceed that budget.
- Outcome: Added both jobs, integrated them into orchestration hooks/queue/workers, added idempotency/replan state helpers, exposed route-level metadata override flags, and added integration tests proving burst-event handling, bounded replanning behavior, and loop resistance.

## Key code changes
- Added orchestration idempotency/replan control utilities:
  - `server/src/services/orchestration/idempotency.ts`
  - Provides stable hashing, `gap_hashes_seen` normalization, read/write helpers for replan iteration state, `decomposition_fingerprint`, and `gap_hash`.

- Added `delta_plan` job:
  - `server/src/services/orchestration/jobs/deltaPlan.ts`
  - Computes unresolved-gap candidates from dependency diagnostics and failed children.
  - Creates only net-new gap-closing children (deterministic child IDs).
  - Persists anti-thrash/idempotency state in node metadata (`decomposition_fingerprint`, `gap_hashes_seen`, `gap_hash`).
  - Enforces bounded replanning via `max_replans` (default 3) unless explicit `replan_budget_override` is set.
  - Emits orchestration events for completed/noop/budget-exhausted outcomes.

- Added `re_review` job:
  - `server/src/services/orchestration/jobs/reReview.ts`
  - Triggered from completion-relevant changes to re-evaluate impacted nodes (dependents and parent).
  - Runs readiness evaluation and conditionally enqueues `delta_plan` using deterministic idempotency keys.
  - Emits `orchestration.re_review.completed` audit events.

- Wired new job types into orchestration runtime:
  - `server/src/services/orchestration/jobQueue.ts`
    - Added `re_review` and `delta_plan` to `OrchestrationJobType`.
  - `server/src/services/orchestration/jobs/index.ts`
    - Registers `startReReviewJobWorker()` and `startDeltaPlanJobWorker()`.
  - `server/src/services/orchestration/hooks.ts`
    - Added status-change completion detection and hook-based `re_review` enqueue with debounce/dedupe windows.
  - `server/src/services/orchestration/watchdog.ts`
    - Watchdog now enqueues direct `evaluate_readiness` / `re_review` actions instead of legacy proxy job types.

- Added explicit replan-budget override input handling:
  - `server/src/routes/tasks.ts`
    - Added `allowReplanBudgetOverride` to task-create payload; persisted to node metadata custom field `replan_budget_override`.
  - `server/src/routes/plans.ts`
    - Added `allowReplanBudgetOverride` to plan-create payload and per-item `taskEdits`; persisted similarly.

- Added integration coverage:
  - `server/src/integration.test.ts`
  - New tests cover:
    - rapid completion bursts with re-review/readiness behavior,
    - bounded replanning and explicit override path,
    - re-review to delta-plan triggering without infinite replanning loops.

## Remaining risks or follow-ups
- `delta_plan` currently uses deterministic gap materialization logic from existing diagnostics/failed-child signals; richer semantic gap extraction may be needed for production-grade replanning quality.
- Replan state is stored in task metadata (`custom` / `idempotency` fields); operational observability and UI surfacing for budget exhaustion/override usage may need follow-up.
- Hook mapping is event-taxonomy-driven; newly introduced event types may require explicit mapping updates to keep re-review coverage complete.
- Debounce/dedupe constants are fixed values and may require tuning under real workload profiles.
