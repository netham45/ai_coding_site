# Task Summary

## Goal and outcome
- Goal: Add core data model support for plan orchestration and hierarchy by introducing plan-level automation fields, plan item polymorphism (execution task vs sub-plan), and missing orchestration status values while preserving existing behavior for legacy data.
- Outcome: Implemented schema and type updates for `auto_start`, `auto_merge_on_complete`, `awaiting_children`, and `plan_revision_items.item_type`; updated project data migration/backfill and verification paths so existing rows remain valid with preserved defaults.

## Key code changes
- `server/src/db/migrations.ts`
  - Added `tasks.auto_start INTEGER NOT NULL DEFAULT 0 CHECK (auto_start IN (0,1))`.
  - Added `tasks.auto_merge_on_complete INTEGER NOT NULL DEFAULT 0 CHECK (auto_merge_on_complete IN (0,1))`.
  - Extended `tasks.status` CHECK to include `'awaiting_children'`.
  - Added `plan_revision_items.item_type TEXT NOT NULL DEFAULT 'execution_task' CHECK (item_type IN ('execution_task','sub_plan'))`.
- `server/src/types.ts`
  - Added `"awaiting_children"` to `TaskStatus`.
  - Added `auto_start` and `auto_merge_on_complete` to `TaskRow`.
  - Added `PlanRevisionItemType = "execution_task" | "sub_plan"`.
  - Added `item_type: PlanRevisionItemType` to `PlanRevisionItemRow`.
- `server/src/db/projectDataMigration.ts`
  - Updated legacy task copy to include `auto_start` and `auto_merge_on_complete`, defaulting both to `0` from legacy source.
  - Updated legacy `plan_revision_items` copy to include `item_type`, defaulting to `'execution_task'`.
  - Updated verification/checksum specs for tasks and plan revision items to include the new columns with backward-compatible source projections.

## Remaining risks or follow-ups
- Runtime/orchestration logic has not yet been expanded to actively use `auto_start`, `auto_merge_on_complete`, `awaiting_children`, or `item_type='sub_plan'`; this task focused on core data model and migration compatibility.
- Existing plan parsing/approval currently creates execution tasks by default; follow-up is needed to parse and instantiate sub-plan items end-to-end.
- Any SQL queries filtering active statuses should be reviewed in future orchestration work to ensure `awaiting_children` is included where intended.
