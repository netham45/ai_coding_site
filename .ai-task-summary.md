## Goal and Outcome

- Goal: Move per-project SQLite databases out of individual project repo folders and into a shared `data` directory to avoid Git interference in cloned repos.
- Outcome: Project DB storage now resolves to `data/projects/<projectId>/project.sqlite`, with automatic migration support from the legacy repo-local path (`<basePath>/.ai-coding/project.sqlite`) when first accessed.

## Key Code Changes

- `server/src/db/projectDb.ts`
  - Added new storage constant and path helper for centralized project DB files:
    - `PROJECT_DB_DATA_DIRNAME = "projects"`
    - `getProjectDbPath(projectId)`
  - Added legacy path helper and migration function:
    - `getLegacyProjectDbPath(basePath)`
    - `moveLegacyProjectDbIfNeeded(...)`
  - Updated `ensureProjectDb(...)` to:
    - Resolve DB path by `projectId` in `data/projects/...`
    - Attempt one-time move from legacy repo-local path before open/validation.
  - Updated `detectProjectDbMetadata(...)` to accept optional `projectId` and support both:
    - New centralized path when `projectId` is provided
    - Legacy path fallback for compatibility.

- `server/src/db/splitPersistence.ts`
  - Updated project DB existence checks to use centralized path (`getProjectDbPath(projectId)`), with legacy path fallback for transition safety.

- `server/src/routes/projects.ts`
  - Removed repo-local `.ai-coding` directory creation during project clone setup (no longer needed for DB placement).

- `server/src/db/index.ts`
  - Exported `getProjectDbPath` and `PROJECT_DB_DATA_DIRNAME` for cross-module/test use.

- `server/src/integration.test.ts`
  - Replaced hardcoded legacy DB file paths with `getProjectDbPath(projectId)`.
  - Updated portability/mismatch scenario to validate metadata mismatch against copied centralized DB path.

- Docs updated to reflect new location:
  - `docs/backup-and-recovery.md`
  - `docs/adr-sqlite-persistence-split.md`
  - `docs/cli-command-architecture.md`

## Remaining Risks or Follow-ups

- Existing docs were updated in key files, but there may be additional lower-priority references to legacy path conventions elsewhere that could still be cleaned up.
- Legacy DB migration currently occurs on project DB access. If there are operational workflows expecting pre-migrated files, a dedicated migration script could be added for bulk proactive moves.
- Verify backup/restore automation in environments outside local test setup to ensure scripts align with `data/projects/<projectId>/project.sqlite`.
