# Task Summary

## Goal and outcome
Goal: Implement the SQLite ownership split defined in `docs/adr-sqlite-persistence-split.md`.
Outcome: Completed. Global entities are persisted in `data/app.sqlite`, and project-local entities are persisted in `<project.base_path>/.ai-coding/project.sqlite`.

## Key code changes
- Split database schemas in `server/src/db/migrations.ts`:
  - App DB: `users`, `user_settings`, `projects`, `project_members`
  - Project DB: `tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`, plus `project_metadata` and `project_config`
- Refactored DB layer in `server/src/db/index.ts`:
  - Added `appDb`
  - Added per-project DB open/init/cache/validation helpers
  - Added metadata validation and project config ownership in project DB
  - Added explicit invariants comments: single source of truth per table, no cross-file FKs, ID-only cross-DB linkage
- Added `server/src/db/ownership.ts` for project/task DB context lookup.
- Rewired routes/services/websocket gateways to use app DB for global auth/membership/settings and project DB for task/plan/runtime/event/IDE/merge data.
- Updated `server/src/types.ts` and `README.md` to match the new persistence model.

## Tests/validation performed
- `npm run build -w server` passed.
- `npm run build` (server + web) passed.

## Remaining risks or follow-ups
- Historical data migration from monolithic runtime/task tables into per-project DBs is not implemented in this task.
- Some cross-project task lookups currently scan project DBs and may need optimization at larger scale.
- Operator tooling for project DB recovery/repair can be expanded.
