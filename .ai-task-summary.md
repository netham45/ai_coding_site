# Task Summary

## Goal and outcome
Goal: Implement the app-vs-project SQLite ownership split in code to match `docs/adr-sqlite-persistence-split.md`.
Outcome: Completed. The system now enforces two persistence layers:
- App DB (`data/app.sqlite`) as source of truth for `users`, `user_settings`, `projects`, `project_members`.
- Per-project DB (`<project.base_path>/.ai-coding/project.sqlite`) as source of truth for project-local entities (`tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`) and project prompt/config fields in `project_config`.

## Key code changes
- Split schema ownership in `server/src/db/migrations.ts`:
  - Added `appBaselineMigration` (global tables only).
  - Added `projectBaselineMigration` (project-local tables + `project_metadata` + `project_config`).
- Refactored DB bootstrap/access in `server/src/db/index.ts`:
  - Replaced monolithic `db` with `appDb` plus project DB open/cache/init helpers.
  - Added metadata validation (`project_metadata.project_id` must match app DB project ID).
  - Added project config read/write helpers and hydration helpers.
  - Added explicit invariants comments: single owner per table, no cross-file FKs, ID-only cross-DB linkage.
- Added ownership resolution helpers in `server/src/db/ownership.ts` for project/task context lookup.
- Rewired routes/services/websockets to use correct owning DB:
  - App/global ownership in auth/settings and project membership checks.
  - Project DB ownership for task/plan/runtime/session/merge/event/IDE state.
- Updated model types in `server/src/types.ts`:
  - Added `AppProjectRow`, `ProjectConfigRow`, and hydrated `ProjectRow`.
- Updated docs in `README.md` to reflect split persistence paths and invariants.

## Remaining risks or follow-ups
- Data migration from any existing monolithic `app.sqlite` task/plan/runtime rows into per-project DB files is not implemented in this task; this is a code/schema ownership cutover.
- Some cross-project task resolution paths currently scan project DBs; functional but may need optimization for very large project counts.
- Operational repair workflows for `PROJECT_DB_UNAVAILABLE` / `PROJECT_DB_CORRUPT` can be expanded with dedicated tooling and runbooks.
