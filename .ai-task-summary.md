## Goal and outcome
- Goal: Let users declare orchestration dependencies across tiers from the UI (not only execution-task IDs), including tier and optional reason, and surface unresolved/blocked upstream references clearly.
- Outcome: Added a reusable dependency picker, integrated it into node creation and plan approval edit flows, and wired hierarchy/dependency-graph data into candidate generation so users can submit `dependencyNodeRefs` across tiers with dedupe/self-dependency prevention in UI.

## Key code changes
- Added `web/src/components/NodeDependencyPicker.tsx`:
  - Reusable dependency row editor with candidate select, tier select, and optional reason input.
  - Candidate badges show status, blocked state, and unresolved upstream reference counts.
  - Enforces UI-level normalization: de-duplicates by `id+tier`, trims reason, and prevents self-dependency when `selfNodeId` is provided.
- Updated `web/src/components/NodeCreateForm.tsx`:
  - Replaced previous ID-only dependency UI with `NodeDependencyPicker`.
  - Submits `dependencyNodeRefs` including `id`, `tier`, and optional `reason`.
- Updated `web/src/pages/ProjectDetailPage.tsx`:
  - Loads both hierarchy and dependency graph (`getHierarchy`, `getDependencyGraph`).
  - Builds richer dependency candidates from hierarchy rows plus dependency-graph nodes.
  - Computes unresolved counts from graph edges and waiting state for clearer upstream context.
- Updated `web/src/pages/TaskDetailPage.tsx`:
  - Loads hierarchy/dependency-graph project context for candidate sourcing.
  - Extends plan item drafts with `dependencyNodeRefs` and renders `NodeDependencyPicker` per proposed plan item.
  - Includes dependency refs in plan approval `taskEdits` payload.
  - Enhances dependency info panel to explicitly display unresolved upstream refs (tier/id/reason/status) when present.
