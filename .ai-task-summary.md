# Task Summary

## Goal and outcome
- Goal: Add CLI commands to list plans, list active tasks, list all tasks, and show task summary/details, with consistent optional `--project-id` and `--plan-id` filters for info-style commands and corresponding database query constraints.
- Outcome: Completed. New CLI commands and aliases were added, service-layer filtered query paths were implemented, and filter handling was wired consistently for task details/info and listing commands.

## Key code changes
- CLI command parsing and help updates:
  - Added optional shared filter parsing for `--project-id` and `--plan-id`.
  - Extended task commands:
    - `tasks all [--project-id] [--plan-id]`
    - `tasks active [--project-id] [--plan-id]`
    - `tasks summary <taskId> [--project-id] [--plan-id]`
    - `tasks details <taskId> [--project-id] [--plan-id]`
  - Updated existing behavior:
    - `tasks list` now routes to all-tasks listing logic.
    - `tasks get` routes to details payload and accepts optional filters.
    - `info <taskId>` routes to filtered task details and accepts optional filters.
    - `plans list` now accepts optional `--project-id` and `--plan-id`.
  - File: `server/src/cli/index.ts`
- Service-layer filtering and query consistency:
  - Added scoped context resolution helper for optional project filtering across accessible projects.
  - Added filtered task lookup helper enforcing both `project_id` and optional `parent_plan_task_id` constraints.
  - Added new service methods:
    - `listAllTasks({ userId, projectId?, planId? })`
    - `listActiveTasks({ userId, projectId?, planId? })`
    - `getTaskSummary({ userId, taskId, projectId?, planId? })`
    - `getTaskDetails({ userId, taskId, projectId?, planId? })`
  - Updated `listPlans` to support optional filters:
    - `listPlans({ userId, projectId?, planId? })`
  - Kept backward-compatible `listTasks({ userId, projectId })` as a delegate to `listAllTasks`.
  - File: `server/src/application/cliServices.ts`

## Tests/validation performed
- TypeScript build:
  - `npm run build -w server` (pass)
- CLI help verification:
  - `npm run cli -w server -- --help` (pass; new commands/flags present)
- Command smoke tests:
  - `npm run cli -w server -- tasks active --json` (pass; valid JSON output)
  - `npm run cli -w server -- plans list --json` (pass; valid JSON output)
- Error/exit-path checks:
  - `npm run cli -w server -- tasks summary not-a-task --json` (not found path, exit code 3)
  - `npm run cli -w server -- tasks details not-a-task --project-id not-a-project --json` (project not found path, exit code 3)

## Remaining risks or follow-ups
- No dedicated CLI integration tests exist yet for new command variants and filter combinations; behavior is currently validated via manual smoke checks.
- `listTasks` now delegates to execution tasks (`mode = 'execution'`) through `listAllTasks`; if previous consumers depended on inclusion/exclusion nuances, add explicit regression tests.
- Some service methods still coexist with overlapping semantics (`getTaskInfo` and `getTaskDetails`); consider consolidating to reduce drift.
