# Task Summary

## Goal and outcome
- Goal: Remove regression logic that hardcoded one child per tier with mirrored auto-generated titles, and ensure decompose no longer synthesizes placeholder children directly.
- Outcome: Completed. Decomposition no longer creates deterministic placeholder descendants. The decompose job now records decomposition context and evaluates readiness without materializing child tasks.

## Key code changes
- Updated decompose orchestration job to remove placeholder child synthesis:
  - Removed deterministic child-ID generation (`auto_<tier>_...`) and mirrored auto-title/prompt synthesis.
  - Removed direct task insertion path (`insertChildNode`) from decomposition.
  - Removed recursive auto-decomposition path that walked tiers by creating synthetic children.
  - Kept decomposition completion event emission, now reporting `nextTier` and `children: []`.
  - Return value now consistently reports `childIds: []`.
- Updated integration tests to assert non-synthesis behavior:
  - Replaced tests that previously expected auto-derived lower-tier descendants.
  - Added assertions that no children are created by decompose for epoch/phase/plan/task roots.

## Remaining risks or follow-ups
- Delta-plan still performs deterministic gap-closing child creation (`delta_<hash>`). If broader policy requires no orchestration-side child materialization at all, that path should be redesigned or feature-gated separately.
- Non-exec node start behavior still routes through orchestration decompose (rather than always starting runtime sessions). If desired behavior is runtime-first for non-exec nodes, start semantics should be aligned across endpoints/services.
- Current plan orchestration still auto-extracts/auto-approves under eligible conditions. If explicit user extract/approve is required, that flow should be disabled or gated and tests/docs updated accordingly.
