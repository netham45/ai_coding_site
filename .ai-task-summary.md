## Goal and outcome
- Goal: Update `ProjectDetailPage` so users can create `epoch`, `phase`, `plan`, and `task` nodes from the existing UI using the unified node creation flow.
- Outcome: Implemented a shared create-node form component and rewired project creation flows to the unified `/nodes` endpoint with tier selection, parent selection, and cross-tier dependency selection.

## Key code changes
- Added `web/src/components/NodeCreateForm.tsx`
  - Introduced reusable create-node form used for both Tasks and Plans tabs.
  - Added required `Node Tier` selector supporting `epoch|phase|plan|task`.
  - Added parent node selector with tier-aware parent constraints.
  - Added dependency selector that supports cross-tier node references (not limited to execution task IDs).
  - Added unified submit payload generation using `dependencyNodeRefs` and optional `parentNodeId`.
  - Kept legacy quick-create behavior as presets by tab (`task` preset in Tasks tab, `plan` preset in Plans tab), but with one shared code path.

- Updated `web/src/pages/ProjectDetailPage.tsx`
  - Replaced separate `Create Task` and `Create Plan` forms with shared `NodeCreateForm` in both tabs.
  - Switched create submission to `createNode(projectId, payload)`.
  - Added hierarchy loading via `getHierarchy(projectId)` and derived node options for parent/dependency selectors.
  - Added tier-aware post-create navigation:
    - execution nodes -> `/tasks/:id?tab=ide`
    - plan-mode nodes (epoch/phase/plan) -> `/plans/:id?tab=ide`
  - Preserved existing tabs, styling, existing plans list, project prompt builder, and IDE pane behavior.

- Updated `web/src/api/types.ts`
  - Corrected `CreateNodeResponse` shape from `{ task: Task }` to `{ node: Task }` to match backend response contract for unified create endpoint.

## Tests/validation performed
- No build/test commands run yet after these edits.

## Remaining risks or follow-ups
- `NodeCreateForm` does not currently include the prior `@file` mention autocomplete behavior that existed in the old task prompt form.
- Parent-tier constraints are implemented in the UI as guided defaults; backend is still the source of truth and may permit/deny additional combinations.
- Since no validation/build was run after edits, TypeScript or lint issues may still exist and should be verified before merge.
- If hierarchy endpoint is unavailable, fallback options are derived from `/tasks` and only infer `task`/`plan` tiers, which may hide `epoch`/`phase` metadata in selectors.
