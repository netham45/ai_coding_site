Goal and outcome
- Goal: Implement `evaluate_readiness(node)` and `decompose(node)` orchestration jobs across tiers with tier-specific prompt selection, deterministic readiness decisions, and auto-mode decomposition from any starting tier.
- Outcome: Added both job handlers, wired them into orchestration hooks/queue/startup, added tier-aware prompt runtime selection and orchestration prompt composition, and added integration tests proving auto decomposition and deterministic readiness behavior.

Key code changes
- Added job types and orchestration hook routing:
  - `server/src/services/orchestration/jobQueue.ts`
    - Extended `OrchestrationJobType` with `evaluate_readiness` and `decompose`.
  - `server/src/services/orchestration/hooks.ts`
    - Hook-to-job mapping now emits readiness jobs for task-scoped events and decompose jobs on node creation.

- Added tier-aware prompt runtime and prompt builder support:
  - `server/src/services/orchestration/promptRuntime.ts`
    - Resolves tier-specific decomposition templates and readiness template, plus shared coordinator template.
  - `server/src/services/promptBuilder.ts`
    - Added `buildTierOrchestrationPrompt(...)` for consistent orchestration prompt composition.

- Implemented readiness job handler:
  - `server/src/services/orchestration/jobs/evaluateReadiness.ts`
    - Computes deterministic readiness decisions from dependencies/children/state.
    - Emits structured `orchestration.readiness.evaluated` events with reason codes, blockers, follow-up jobs, and idempotency key.
    - Updates metadata lifecycle reason code and applies guarded state transitions through state machine checks.

- Implemented decomposition job handler:
  - `server/src/services/orchestration/jobs/decompose.ts`
    - Tier progression: `epoch -> phase -> plan -> task -> exec`.
    - Supports auto-mode recursive decomposition from any starting tier.
    - Uses deterministic child IDs and emits structured `orchestration.decompose.completed` events.
    - Integrates readiness evaluation for parent/child progression.

- Wired hierarchical jobs into startup:
  - `server/src/services/orchestration/jobs/index.ts`
  - `server/src/index.ts`
    - Registers and starts hierarchical orchestration job workers.

- Added integration coverage:
  - `server/src/integration.test.ts`
    - New suite: `integration: hierarchical decomposition and readiness jobs`.
    - Validates epoch start auto-derives lower tiers.
    - Validates phase/plan/task starts derive only downstream tiers.
    - Validates readiness idempotency key determinism and reason-code behavior.

Remaining risks or follow-ups
- Current decomposition materializes deterministic auto-child nodes and orchestration prompts, but does not yet execute LLM parsing/materialization logic for domain-specific child DAGs beyond the deterministic tier chain.
- Hook mapping controls when readiness/decompose fire; new event taxonomies may require additional mappings to maintain expected orchestration coverage.
- Readiness reason-code assignment is deterministic and guard-aware, but policy tuning may be needed for nuanced plan/exec lifecycle semantics under production workloads.
- Prompt template references use existing prompt artifacts and shared template; if upstream template contracts evolve, prompt runtime selection/composition may require updates.
