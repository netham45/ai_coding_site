## Goal and outcome
- Goal: prevent divergence by making legacy create routes (`/projects/:projectId/tasks` and `/projects/:projectId/plans`) thin wrappers around the unified node creation behavior.
- Outcome: implemented shared creation logic in `tasks.ts` and routed all three create endpoints (`/nodes`, `/tasks`, `/plans`) through it while preserving legacy response shapes and tier defaults.

## Key code changes
- `server/src/routes/tasks.ts`
  - Added exported shared helper `createProjectNode(...)` with a typed input contract covering unified and legacy creation use cases.
  - Moved workspace initialization, dependency resolution/validation, metadata construction, insert/transition writes, event recording, and queue kick into shared logic.
  - Kept endpoint contracts:
    - `POST /projects/:projectId/nodes` returns `{ node }` and uses `source: "unified"`.
    - `POST /projects/:projectId/tasks` returns `{ task }` and uses `source: "legacyTask"`.
  - Preserved tier defaults:
    - legacy tasks map to `nodeTier: "task"`.
    - unified endpoint behavior for `epoch|phase|plan|task` unchanged.

- `server/src/routes/plans.ts`
  - Updated `POST /projects/:projectId/plans` to be a thin wrapper:
    - still applies planner prompt formatting (`buildPlanTaskPrompt(...)`).
    - delegates creation to `createProjectNode(...)` with `source: "legacyPlan"`.
    - still returns `{ plan }`.
  - Preserved tier default for plans (`nodeTier: "plan"`).

- `server/src/integration.test.ts`
  - Expanded integration coverage by updating the unified-node creation test to cover both legacy and unified paths in one flow.
  - New assertions verify:
    - legacy `/plans` create succeeds with `mode: "plan"` and metadata `tier: "plan"`.
    - legacy `/tasks` create succeeds with `mode: "execution"`, metadata `tier: "task"`, and dependency persistence.
    - unified `/nodes` still creates `epoch/phase/plan/task` with expected modes, parent linkage, and dependencies.

## Remaining risks or follow-ups
- `plans.ts` now imports creation logic from `tasks.ts`; this is intentional for shared behavior, but route-level coupling is increased. A follow-up extraction into a dedicated shared service module could reduce coupling.
- Error response text parity is preserved for known legacy parent-plan validation cases, but any undocumented reliance on exact wording for other failure paths should be verified by consumers.
- Only targeted integration coverage was added/updated for this refactor path; if desired, add explicit event-payload assertions for legacy wrappers to lock payload compatibility over time.
