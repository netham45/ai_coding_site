# Task Summary

## Goal and Outcome
- Goal: Create the runtime prompt template that decomposes a Phase node into Plan children, with strict contract-aligned inputs/outputs and support for both initial decomposition and refinement.
- Outcome: Added a new `prompts/phase-to-plans.md` artifact that defines required inputs, decomposition rules, structured output schema, and validation rules; also updated prompt index documentation.

## Key Code Changes
- Added `prompts/phase-to-plans.md`:
  - Defines required runtime inputs:
    - `mode` (`initial` or `refine`)
    - `phase_spec`
    - `epoch_goals`
    - `dependency_statuses`
    - `previous_synthesis`
    - `previous_verification`
    - `repository_context`
  - Adds decomposition constraints for sequencing, dependency fan-in/fan-out, deliverable boundaries, and stable plan IDs across refinement.
  - Requires dual output:
    - Natural-language decomposition rationale
    - Structured YAML payload aligned to `docs/architecture/prompt-contract.md`
  - Includes structured payload skeleton with required contract fields:
    - `goals`, `non_goals`, `definition_of_done`, `deps`, `artifacts`, `risks`, `idempotency`, `bounded_iteration`, `auto_merge_guidance`
  - Adds phase-specific sections:
    - `plan_children` (plan-level DoD, dependencies/reasons, touched modules/artifacts, risks, idempotency, iteration controls, auto-merge defaults)
    - `change_summary` (initial/refine diff tracking and refinement reason)
  - Adds explicit validation rules (e.g., `node.tier=phase`, plan child IDs must map to `node.children_ids`, dependency entries require `id` + `reason`).
- Updated `prompts/README.md`:
  - Added `phase-to-plans.md` to the runtime prompt artifact index.
