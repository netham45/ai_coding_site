Goal and outcome
- Goal: Implement workflow stage action execution for `run_command`, `task_runtime_prompt`, `create_child_nodes_from_plan_yaml`, `review_child_nodes`, and `no_op` with idempotent behavior and workflow-event auditability.
- Outcome: Added a new stage action execution service that supports all five action types, records start/success/failure audit events, enforces stage status transitions, returns idempotent replay results for repeated idempotency keys, and captures structured failure reasons.

Key code changes
- Added stage action execution service:
  - `server/src/services/workflowStageActions.ts`
  - New action union type: `WorkflowStageActionType`
  - New entry point: `executeWorkflowStageAction(...)`
  - Added structured failure reason type: `StructuredActionFailureReason`
  - Added handler override hooks for each action type to allow integration wiring and deterministic tests
  - Added default behavior for each action type:
    - `run_command`: shell execution via `bash -lc` with timeout/env/cwd handling
    - `task_runtime_prompt`: validates and records prompt acceptance metadata
    - `create_child_nodes_from_plan_yaml`: parses plan YAML and returns child node summary
    - `review_child_nodes`: evaluates child status list and returns review summary
    - `no_op`: explicit no-op result
  - Idempotency implementation:
    - Explicit key support or deterministic derived key from action type + stage id + normalized input
    - Replays prior `workflow.stage.action.completed` / `workflow.stage.action.failed` event outcomes without re-executing
  - Audit event implementation in `workflow_events`:
    - `workflow.stage.action.started`
    - `workflow.stage.action.completed`
    - `workflow.stage.action.failed`
  - Stage status transitions integrated:
    - `pending -> running` on first execution
    - `running -> succeeded` on success
    - `running -> failed` on failure
- Extended workflow repository API:
  - `server/src/services/workflowRepository.ts`
  - Added `listWorkflowEventsByStageRun(db, workflowStageRunId)` to support stage-level audit replay and verification
- Added tests:
  - `server/src/services/workflowStageActions.test.ts`
  - Covers all five action types, event recording, idempotent replay behavior, and structured failure reason persistence
