# Task Summary

## Goal and outcome
- Goal: Implement a top-level CLI executable with structured subcommands for plans, tasks, info, session, create, review, ide, ready_merge, and merge, with shared argument parsing/help/exit codes and service-layer wiring.
- Outcome: Completed. A new CLI entrypoint and reusable service layer were added, and the server build/CLI behaviors were validated.

## Key code changes
- Added reusable CLI application service module:
  - `server/src/application/cliServices.ts`
- Added top-level CLI executable:
  - `server/src/cli/index.ts`
- Added server CLI npm script:
  - `server/package.json` (`"cli": "tsx src/cli/index.ts"`)
- Implemented command tree and aliases:
  - `tasks`: `list|get|create|start|input|pull-main`
  - `plans`: `list|create|get|extract|regenerate|approve`
  - `info <taskId>`
  - `session start|input`
  - `create task|plan` (aliases)
  - `review <taskId>`
  - `ide status|start|stop`
  - `ready_merge <taskId>`
  - `merge <taskId>`
- Added shared CLI infrastructure:
  - Argument parsing for flags and positionals
  - `--help` and `--json` support
  - Exit code contract mapping:
    - `0` success
    - `2` invalid args/validation
    - `3` not found
    - `4` conflict/precondition
    - `5` unavailable (project DB unavailable)
    - `1` internal/unhandled
- Ensured help path avoids unnecessary DB initialization by lazily importing DB/service modules.

## Tests/validation performed
- TypeScript compile:
  - `npm run build -w server` (pass)
- CLI help output:
  - `npm run cli -w server -- --help` (pass)
- CLI not-found behavior and exit-code path:
  - `npm run cli -w server -- tasks list --project not-a-project --json` (returned not-found error and non-zero exit path as expected)
- Verified repository changes via `git status --short`.

## Remaining risks or follow-ups
- Route handlers still contain duplicated domain logic; new CLI services currently replicate/centralize behavior for CLI but routes are not yet refactored to call the same application service module.
- No dedicated CLI integration test suite yet; recommend adding tests for parsing, exit codes, and parity with API behaviors.
- Human-friendly non-JSON output currently uses pretty JSON; could be enhanced with concise tables/formatters.
