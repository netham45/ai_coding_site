# Task Summary

## Goal and outcome
- Goal: Update plan prompt instruction builders and parsing so plan revisions can represent mixed plan items (`execution_task` + `sub_plan`), explicit dependencies across all items, and automation expectations for auto-executable/auto-mergeable flows.
- Outcome: Implemented richer planner output contract instructions in both API and CLI planning prompts, extended `planParser` to parse/validate mixed-item YAML with dependency checks and cycle detection, and wired parsed item types/automation defaults into extraction and approval flows while preserving backward compatibility with legacy task-only YAML.

## Key code changes
- `server/src/services/planParser.ts`
  - Extended parsed model:
    - Per-item: `itemType`, `autoMerge`, `autoStart`, `autoMergeOnComplete`.
    - Plan-level: `autoStart`, `autoMergeOnComplete`, `autoMergeItemKeys`.
  - Added parsing support for richer schema:
    - Item keys: `item_type`/`type`, `auto_merge`, `auto_start`, `auto_merge_on_complete`, `depends_on`.
    - Top-level defaults: `auto_start`, `auto_merge_on_complete`, `auto_merge_item_keys`.
    - Compatibility for `tasks:` and `items:` top-level list key.
  - Added/strengthened validation:
    - Missing dependency detection and cycle detection across all item types.
    - Item-type automation constraints (e.g., execution items cannot set sub-plan automation flags).
    - Deduplicated dependency keys.
  - Preserved legacy behavior:
    - Legacy YAML with only `tasks`/`id`/`title`/`prompt`/`depends_on` remains valid and defaults to `execution_task`.

- `server/src/routes/plans.ts`
  - Updated planning instruction contract text to request mixed item types, dependency DAG requirements, and automation fields.
  - In `/plans/:planId/extract`, now persists `plan_revision_items.item_type` from parsed output.
  - In `/plans/:planId/approve`, now derives defaults from parsed revision YAML (`latestRevision.raw_output`) when explicit approve payload overrides are not provided:
    - item type fallback,
    - execution auto-merge hints,
    - sub-plan auto-start and auto-merge-on-complete defaults.

- `server/src/application/cliServices.ts`
  - Mirrored the same planning instruction updates used in routes.
  - In `extractPlan`, now persists `plan_revision_items.item_type`.
  - In `approvePlan`, mirrored parsed revision default behavior for item type and automation fallback.

- `server/src/integration.test.ts`
  - Added parser-focused tests:
    - Accepts mixed item types + automation defaults.
    - Backward compatibility for legacy task-only YAML.
    - Rejects cyclic dependencies spanning mixed item types.

## Remaining risks or follow-ups
- Planner instruction text was updated in route/CLI planning builders; if any additional prompt instruction builders exist outside these paths, they should be reviewed for parity.
- Approval fallback now reparses `latestRevision.raw_output`; malformed stored raw output falls back to DB row defaults. This is safe but should be monitored if historical malformed revisions are common.
- Dependency validation currently enforces existence and acyclic graph over item keys; if future schema adds conditional/soft dependencies, parser and approval logic will need extension.
- No end-to-end integration test yet exercises full extract+approve automation propagation from generated YAML through created tasks/sub-plans in one scenario.
