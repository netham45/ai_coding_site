Goal and outcome
- Goal: Implement `synthesize(parent)` and `verify(parent)` orchestration jobs, enforce parent completion correctness with a verification feedback loop, and persist synthesis/verification artifacts including requirement->evidence coverage mapping.
- Outcome: Added deterministic synthesis and verification flows, wired them into orchestration hooks/job queue/workers, enforced completion gating in parent auto-advance, persisted linked artifacts in metadata/events, and added integration coverage validating the new behavior.

Key code changes
- Added parent completion orchestration module:
  - `server/src/services/orchestration/completion.ts`
  - Implements:
    - parent resolution for completion checks,
    - `runSynthesizeForParent(...)` summary + coverage matrix generation,
    - `runVerifyForParent(...)` verdict generation with bounded `delta_plan` enqueue on failure,
    - artifact persistence via `orchestration.synthesize.completed` / `orchestration.verify.completed` events,
    - metadata links and lifecycle flags (`synthesis_artifact_event_id`, `verification_artifact_event_id`, `verification_verdict`, `lifecycle.synthesis_passed`, `lifecycle.verification_passed`).

- Added new orchestration jobs:
  - `server/src/services/orchestration/jobs/synthesize.ts`
  - `server/src/services/orchestration/jobs/verify.ts`
  - Registered via `server/src/services/orchestration/jobs/index.ts`.

- Extended orchestration job system and hook routing:
  - `server/src/services/orchestration/jobQueue.ts`
    - Added job types: `synthesize`, `verify`.
  - `server/src/services/orchestration/hooks.ts`
    - On child completion-like `task.status_changed`, now enqueues `synthesize` and `verify` (with debounce/dedupe) in addition to existing jobs.

- Enforced parent completion correctness in CLI parent auto-advance path:
  - `server/src/application/cliServices.ts`
  - `maybeAdvanceParentPlanAfterChildMerge(...)` now runs completion feedback before setting parent `merge_ready`; blocks advancement and emits `plan.parent_completion.blocked` when verification gate is not satisfied.

- Prompt/runtime updates for new job actions:
  - `server/src/services/orchestration/promptRuntime.ts`
    - Added job variants `synthesize` and `verify` with template paths.
  - `server/src/services/promptBuilder.ts`
    - Extended orchestration action union to include `synthesize` and `verify`.
  - Added template:
    - `prompts/verification.md` (used as `ip-10` verification template path).
  - Existing `prompts/synthesis.md` is used for synthesis (`ip-09`).

- Added integration coverage:
  - `server/src/integration.test.ts`
  - New tests verify:
    - synthesis artifact persistence and coverage matrix requirement/evidence structure,
    - verify failure behavior with deterministic verdict artifact and bounded delta-work feedback path,
    - no regressions in existing completion/auto-merge orchestration flows.

Remaining risks or follow-ups
- Coverage extraction and evidence matching are deterministic heuristics over prompt/results; richer semantic requirement parsing/evidence attribution may be needed for production-grade quality.
- Verification currently treats uncovered requirements and child-state constraints as fail signals; policy thresholds (for partial coverage and staged completion) may need tuning per workflow.
- New verification template is present as `prompts/verification.md`; if strict artifact naming/contracts for `ip-10` evolve, template mapping should be aligned accordingly.
- Artifact retention continues in `events`; long-term pruning/archival strategy may be required to prevent unbounded growth.
