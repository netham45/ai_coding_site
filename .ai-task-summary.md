# Task Summary

## Goal and Outcome
- Goal: Fix rerun behavior so it only clears the task folder and resets task state to `queued`, without re-cloning or other repo re-initialization.
- Outcome: Implemented. Rerun now clears the workspace directory, recreates it empty, and updates task state to `queued`. No clone/branch setup happens during rerun.

## Key Code Changes
- Backend rerun endpoint updated in `server/src/routes/tasks.ts`:
  - Removed rerun-time dependency on project clone readiness and topology resolution.
  - Removed rerun-time calls to `cloneLocalBaseToWorkspace(...)` and `createTaskBranch(...)`.
  - Kept workspace safety guard (`isSafeTaskWorkspacePath(...)`).
  - Rerun now:
    - Deletes workspace path recursively.
    - Recreates workspace directory as empty.
    - Resets task fields and sets `status = 'queued'`.
  - `base_commit_sha_at_create` is reset to `NULL` on rerun.
  - `task.rerun` event payload no longer includes `baseCommitShaAtCreate`.

- Frontend rerun UX updated in `web/src/pages/TaskDetailPage.tsx`:
  - Confirmation copy updated to reflect “clear workspace + reset to queued” behavior.
  - Removed automatic post-rerun calls to:
    - `POST /api/tasks/:id/start`
    - `POST /api/tasks/:id/ide/start`
  - Success toast changed from “Task re-run started” to “Task reset to queued”.

## Remaining Risks or Follow-ups
- Existing runtime start behavior still recreates workspace from source if `.git` is missing. Since rerun now leaves an empty directory, starting the task later will re-clone at start time. This matches the requested rerun semantics (no clone during rerun), but clone still happens when task execution begins.
- No dedicated integration test currently targets rerun-specific semantics; adding one would lock in this behavior and prevent regressions.
- If product expectation is strict “never clone on rerun and never clone on immediate start after rerun,” runtime start logic would need an additional design decision and change.
