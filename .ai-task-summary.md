# Task Summary

## Goal and outcome
- Goal: Add plan completion detection and automatic merge behavior so when the last required child item is merged, the parent plan transitions to merge-ready and auto-merges into its correct parent target (parent plan workspace for nested plans, or project base for top-level plans), with plan-specific conflict/failure handling and recovery semantics.
- Outcome: Implemented parent-plan completion orchestration in merge flow, enabled automatic merge-ready/auto-merge transitions for eligible plans, preserved non-fatal failure handling, fixed nested plan merge topology resolution, and validated behavior with new integration tests.

## Key code changes
- `server/src/application/cliServices.ts`
  - Added `maybeAdvanceParentPlanAfterChildMerge(...)`:
    - Detects parent plan after child merge.
    - Moves parent plan to `awaiting_children` while required children remain.
    - Moves parent plan to `merge_ready` when all required children are merged.
    - Executes `mergePlan(...)` automatically when `auto_merge_on_complete=1`.
    - Emits plan events for awaiting/auto-ready and auto-merge failure tracking.
  - Added `refreshTaskRow(...)` helper.
  - Updated `MERGE_READY_ALLOWED_FROM` to include `awaiting_children`.
  - Hooked parent-plan advancement after successful `mergeTask(...)` and successful `mergePlan(...)` (supports recursive/nested plan completion).
  - Fixed nested plan merge topology in `mergePlan(...)` by resolving and passing `parentPlanTask` into `resolveTaskGitTopology(...)`.
- `server/src/integration.test.ts`
  - Added test: `merging the last child auto-marks parent plan merge-ready and auto-merges when enabled`.
  - Added test: `plan auto-merge on completion records conflict and supports merge-ready recovery`.
  - Added assertions that no `plan.auto_merge_on_complete.failed` event is emitted in these expected paths.

## Remaining risks or follow-ups
- Automatic parent-plan merge is currently implemented in CLI service merge paths; equivalent direct HTTP route merge handlers still contain duplicated merge logic and may be a candidate for consolidation to ensure a single orchestration path.
- Auto-merge failure handling records events and leaves parent state for operator recovery; additional retries/backoff policy could improve unattended recovery behavior.
- Additional telemetry (rate/latency/conflict metrics) around parent-plan auto-merge progression may improve observability in larger DAGs.
