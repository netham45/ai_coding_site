# Task Summary

## Goal and outcome
Goal: Implement the app-vs-project SQLite persistence ownership split defined in `docs/adr-sqlite-persistence-split.md`.
Outcome: Completed. Global entities remain in `data/app.sqlite`, and project-local entities were moved to per-project DB files at `<project.base_path>/.ai-coding/project.sqlite`, with project config fields owned by project DB.

## Key code changes
- Split schema definitions in `server/src/db/migrations.ts`:
  - App DB: `users`, `user_settings`, `projects`, `project_members`
  - Project DB: `tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`, plus `project_metadata` and `project_config`
- Refactored DB layer in `server/src/db/index.ts`:
  - Added `appDb`
  - Added project DB open/init/cache/validation helpers
  - Added metadata and config handling for per-project DB
  - Added explicit invariants comments (single owner per table, no cross-file FKs, ID-only cross-DB linkage)
- Added ownership context helpers in `server/src/db/ownership.ts` for project/task resolution.
- Rewired app code to enforce ownership boundaries:
  - Updated routes/services/ws modules to use app DB for global auth/membership/settings and project DB for task/plan/runtime/event/IDE/merge state.
- Updated types in `server/src/types.ts` (`AppProjectRow`, `ProjectConfigRow`, hydrated `ProjectRow`).
- Updated README docs for split persistence and invariants.
