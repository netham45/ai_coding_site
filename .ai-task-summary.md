# Task Summary

## Goal and outcome
Goal: Update app DB migrations/bootstrap so `projects` retains only global project metadata, remove project-local prompt/config columns from app DB ownership, and provide a compatibility migration path for existing app DBs.
Outcome: Completed. App DB `projects` remains global-only, and startup now includes a compatibility migration that rebuilds legacy app DB `projects` tables when project-local columns still exist.

## Key code changes
- Updated `server/src/db/index.ts`:
  - Added `tableColumns()` helper for schema introspection.
  - Added `migrateProjectsToGlobalMetadataOnly(appDb)` compatibility migration:
    - Detects legacy app DB columns on `projects` (`project_prompt`, `project_rules`, `coding_standard`, `coding_standard_other`, `project_other`).
    - Rebuilds `projects` into the global-metadata-only schema using `projects_new` inside a transaction.
    - Preserves only global project fields used for listing/membership/global settings behaviors.
    - Recreates key project indexes after rebuild.
- Verified schema ownership remains aligned with split persistence in `server/src/db/migrations.ts`:
  - App DB `projects` contains global metadata only.
  - Project-local prompt/config fields are owned by project DB `project_config`.

## Tests/validation performed
- Ran `npm run build -w server`.
- Result: passed (`tsc -p tsconfig.json`).

## Remaining risks or follow-ups
- Existing app DB values in removed prompt/config columns are not copied to per-project DB `project_config` by this compatibility path; if those values are still needed, add an explicit data-migration step.
- Runtime verification should be performed against a representative legacy `data/app.sqlite` to confirm migration behavior and startup reliability.
