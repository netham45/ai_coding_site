# Task Summary

## Goal and outcome
- Goal: Implement an auto-merge conflict flow that preserves stage intent using parent+child specs, enforces verification/merge gates, and supports retry/escalation hooks.
- Outcome: Added a conflict-resolution orchestration module, enforced merge gates before task/plan merges, attached structured intent-preserving conflict artifacts on merge conflicts, emitted merge completion/failure hook events, added missing prompt artifact documentation, and validated behavior with integration tests.

## Key code changes
- Added conflict-resolution orchestration service:
  - `server/src/services/orchestration/conflictResolution.ts`
  - Implements merge gate checklist generation, required-gate evaluation helpers, failed-gate descriptions, and intent-preserving conflict artifact generation with:
    - prompt template path (`prompts/intent-preserving-conflict-resolution.md`)
    - conflict inputs (`parent_spec`, `child_spec`, conflict hunks, verification constraints, merge context)
    - structured `conflict_resolution` payload (`patch_plan`, intent justification, merge-gate checklist, unresolved conflicts, escalation + retry policy)

- Wired task/plan merge flows to conflict orchestration and gating:
  - `server/src/application/cliServices.ts`
  - `mergeTask(...)` and `mergePlan(...)` now:
    - compute/check merge gates before merge attempts (status, dependencies, clean workspace, and plan synthesis/verification/child guards)
    - reject merge when required gates fail (`Merge gates failed: ...`)
    - build/emit structured conflict-resolution artifact on merge conflicts via `task.merge_conflict` / `plan.merge_conflict`
    - emit explicit failure events (`task.merge_failed` / `plan.merge_failed`) on merge exceptions

- Extended events/hook observability:
  - `server/src/services/events.ts`
  - Persists hook audit events:
    - `orchestration.hook.on_merge_completed` for merged events
    - `orchestration.hook.on_merge_failed` for conflict/failure events

- Expanded merge-failure hook mapping:
  - `server/src/services/orchestration/hooks.ts`
  - Treats `task.merge_failed` and `plan.merge_failed` as `on_merge_failed` sources.

- Added missing prompt artifact and index entry:
  - `prompts/intent-preserving-conflict-resolution.md`
  - `prompts/README.md` updated with template listing.

- Added integration coverage:
  - `server/src/integration.test.ts`
  - New checks verify:
    - conflict event payload includes conflict-resolution artifact, patch plan, escalation flag, and prompt path
    - merge-failed hook audit event is persisted
    - plan merge is blocked when verification gate is not satisfied, even if status is `merge_ready`

## Tests/validation performed

  - `npm run build` (passed)

## Remaining risks or follow-ups
- Conflict artifact generation is currently deterministic/template-driven and not yet backed by runtime schema validation for payload shape at all boundaries.
- Conflict resolution artifacts are emitted on conflict events, but no automatic patch application loop is implemented yet; current escalation policy remains manual fix + retry.
- Hook audit events are persisted directly in `recordEvent`; if stricter idempotency or dedupe for hook-audit rows is required, add an event-key strategy.
- Merge gate checks currently enforce clean workspace and verification flags at merge time; if policy should also hard-fail stale summaries/evidence freshness, add explicit age/hash checks.
