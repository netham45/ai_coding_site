# Task Summary

## Goal and outcome
- Goal: refactor database migrations into separate app and project migration sets, keeping `users`, `user_settings`, `projects`, and `project_members` in app DB, moving task/runtime/plan/merge/event tables to project DB, and adding a project-local config table for prompt/config fields previously on `projects`.
- Outcome: completed for schema and project config ownership wiring. App and project migration sets were split, project DB now creates/maintains `project_config`, and project routes read/write prompt/config through project DB.

## Key code changes
- Updated `server/src/db/migrations.ts`:
  - Replaced monolithic `baselineMigration` with:
    - `appBaselineMigration` (`users`, `user_settings`, `projects`, `project_members`).
    - `projectBaselineMigration` (`tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`).
  - Added `project_config` table in project schema with:
    - `project_id` (PK), `project_prompt`, `project_rules`, `coding_standard`, `coding_standard_other`, `project_other`, `created_at`, `updated_at`.
- Updated `server/src/db/appDb.ts`:
  - Switched initialization from old baseline to `appBaselineMigration`.
  - Removed legacy app-side migrations for task and project-config columns/tables that no longer belong in app DB ownership.
- Updated `server/src/db/projectDb.ts`:
  - Runs `projectBaselineMigration` during project DB initialization.
  - Added `ProjectConfigRow` type and helpers:
    - `getProjectConfig({ projectId, basePath })`
    - `upsertProjectConfig({ projectId, basePath, ...config })`
  - Ensures per-project `project_config` row exists.
- Updated `server/src/db/index.ts`:
  - Re-exported `getProjectConfig` and `upsertProjectConfig`.
- Updated `server/src/routes/projects.ts`:
  - Removed app DB writes of prompt/config columns from project insert/update SQL.
  - Added hydration logic to combine app `projects` row with project DB config.
  - On successful clone, seeds project DB config via `upsertProjectConfig` from create payload.
  - Patch endpoint now writes config updates to project DB.
- Updated `server/src/services/promptBuilder.ts`:
  - Added null-safe reads for config fields (`?? ""`) before trimming.

## Tests/validation performed
- Ran `npm run build -w server` after the refactor.
- Result: successful TypeScript compilation with no errors.

## Remaining risks or follow-ups
- Runtime and task/plan/event data access is still largely wired to app DB handle usage in route/service modules. Since those tables are now in project schema ownership, a full cutover to project DB handles (`getProjectDb`) is still required for complete end-to-end correctness.
- No explicit data migration/backfill was added in this task to move existing prompt/config values from legacy app `projects` columns into `project_config` for already-existing projects.
- Missing/corrupt project DB behaviors for read/write endpoints beyond current fallbacks should be handled consistently across all project-scoped operations.
