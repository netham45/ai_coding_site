# Task Summary

## Goal and outcome
Goal: Implement the SQLite app-vs-project ownership split defined in `docs/adr-sqlite-persistence-split.md`.
Outcome: Completed. Global entities are owned by `data/app.sqlite`, and project-local entities are owned by per-project databases at `<project.base_path>/.ai-coding/project.sqlite`.

## Key code changes
- Split schema definitions in `server/src/db/migrations.ts`:
  - App DB owns: `users`, `user_settings`, `projects`, `project_members`
  - Project DB owns: `tasks`, `task_dependencies`, `task_state_transitions`, `task_sessions`, `plan_revisions`, `plan_revision_items`, `plan_revision_item_dependencies`, `ide_instances`, `merge_records`, `events`, and project config via `project_config`
- Refactored DB bootstrap/access in `server/src/db/index.ts`:
  - Added `appDb`
  - Added project DB open/init/cache/validation
  - Added metadata validation and config ownership helpers
  - Added explicit invariants comments: single source of truth per table, no cross-file FKs, ID-only cross-DB linkage
- Added ownership/context helper module `server/src/db/ownership.ts`.
- Rewired routes/services/ws modules to use correct DB ownership boundaries.
- Updated types in `server/src/types.ts` and docs in `README.md`.

## Tests/validation performed
- `npm run build -w server` passed.
- `npm run build` (server + web) passed.

## Remaining risks or follow-ups
- Historical data migration from monolithic runtime/task tables into per-project DB files is not included in this change.
- Some cross-project task lookups are scan-based and may need optimization at scale.
- Operational tooling for project DB repair/recovery flows can be expanded.
