# Task Summary

## Goal and Outcome
- Goal: Create a full runtime prompt template for exec task execution that enforces a safe code-change workflow and captures verifiable execution evidence.
- Outcome: Added a new exec-tier runtime template that requires baseline repo context, mandatory validation/test evidence, PR-ready reporting, rollback/conflict notes, and structured auto-merge readiness signals.

## Key Code Changes
- Added new prompt artifact:
  - `prompts/exec-task-runner.md`
  - Defines required inputs for:
    - node metadata (`node.*`)
    - repo status (branch, tracking branch, working tree summary, HEAD)
    - branch lineage (base/execution/merge target, divergence constraints)
    - acceptance checks (required commands and evidence expectations)
    - merge assumptions (branch protections/check requirements/conflict policy)
  - Enforces a safe edit workflow:
    1. Scope/non-goals confirmation
    2. Baseline git evidence capture
    3. Minimal reversible edits
    4. Required checks gate
    5. Command evidence capture
    6. PR-ready delta summary
    7. Rollback/conflict notes
  - Adds completion gates requiring passing checks or explicit blocker ownership, complete touched-file accounting, risk mitigation, and merge-safe notes.
  - Requires dual output shape:
    - natural-language execution summary
    - structured YAML payload with prompt-contract fields plus `execution_report` containing:
      - repo baseline/final heads and branch targets
      - touched files with change type and summary
      - command evidence with exit codes/outcomes
      - acceptance check results and evidence refs
      - PR-ready summary
      - merge-safe notes (assumptions/blockers/conflict risk/rollback plan)
  - Defines failure handling to keep `auto_merge_guidance.eligible: false` when blockers exist.

- Updated artifact index:
  - `prompts/README.md`
  - Added `exec-task-runner.md` to the runtime template file list.

## Tests/Validation Performed

- Follow-up: wire `execution_report` validation into extraction/approval/execution boundaries so missing check evidence fails materialization automatically.
- Follow-up: add integration tests for exec outputs that should fail on missing required check evidence, missing touched-file accounting, or inconsistent auto-merge eligibility.
