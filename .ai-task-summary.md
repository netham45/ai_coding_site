# Task Summary

## Goal and outcome
- Goal: Extend plan creation/approval/list/get contracts to expose and accept new automation and hierarchy controls: plan auto-start mode, plan auto-merge behavior, and parent-plan targeting for sub-plans; keep HTTP routes and CLI services behaviorally aligned.
- Outcome: Implemented route/service/CLI contract updates for `autoStart`, `autoMergeOnComplete`, and `parentPlanTaskId`, added plan-item polymorphism handling (`execution_task` vs `sub_plan`) in approval flows, and exposed the new fields consistently in serialized plan/task payloads.

## Key code changes
- `server/src/routes/plans.ts`
  - Extended request schemas:
    - `createPlanSchema`: added `autoStart`, `autoMergeOnComplete`, `parentPlanTaskId`.
    - `approvePlanSchema`: added top-level defaults (`autoStart`, `autoMergeOnComplete`, `parentPlanTaskId`) and per-item overrides (`itemType`, `parentPlanTaskId`, `autoStart`, `autoMergeOnComplete`).
  - Updated plan creation logic:
    - Validates optional parent plan target in project.
    - Clones from parent plan branch when `parentPlanTaskId` is provided, otherwise from project default branch.
    - Persists `auto_start` and `auto_merge_on_complete` for created plan tasks.
  - Updated plan approval logic:
    - Supports creating both execution tasks and sub-plans from revision items.
    - Supports parent-plan targeting for sub-plans, including explicit `null` (root project target).
    - Persists per-created-task mode and automation flags.
    - Creates `.ai-plan` directory for spawned sub-plan workspaces.
  - Updated serializers/get payloads:
    - Task serialization now includes `autoStart` and `autoMergeOnComplete`.
    - Plan revision item payload now includes `itemType`.
  - Updated embedded CLI usage/help text to include new plan flags.

- `server/src/application/cliServices.ts`
  - Mirrored `routes/plans.ts` behavior for CLI services:
    - `createPlan` signature/logic supports `autoStart`, `autoMergeOnComplete`, `parentPlanTaskId`.
    - `approvePlan` signature/logic supports default and per-item plan hierarchy/automation controls and item polymorphism.
    - `getPlan` revision item serialization includes `itemType`.
    - Task serialization includes `autoStart` and `autoMergeOnComplete`.
  - Updated planning usage instructions to include new plan flags.

- `server/src/cli/index.ts`
  - Extended CLI parsing/wiring:
    - `plans create` accepts/passes `--auto-start`, `--auto-merge-on-complete`, `--parent-plan-id`.
    - `plans approve` accepts/passes `--auto-start`, `--auto-merge-on-complete`, `--parent-plan-id`.
  - Extended `TaskEdit` type to support new per-item fields (`itemType`, plan targeting, automation overrides).
  - Updated help text for `plans create` and `plans approve`.

- `server/src/routes/tasks.ts`
  - Task serializer now exposes `autoStart` and `autoMergeOnComplete` for route parity.

- `server/src/services/promptBuilder.ts`
  - Updated CLI usage block text to include new plan flags.

- `web/src/api/types.ts`
  - Updated client types to match API contract updates:
    - `TaskStatus` includes `awaiting_children`.
    - `Task` includes `autoStart` and `autoMergeOnComplete`.
    - `PlanRevisionItem` includes `itemType`.

- `server/src/integration.test.ts`
  - Added assertions to validate new CLI help text options.
  - Added assertions that listed plans expose `autoStart` and `autoMergeOnComplete` fields.
