Goal and outcome
- Goal: Implement `on_node_output_updated` with material-change hashing/debounce and add an optional `on_timer_tick` watchdog for stalled orchestration.
- Outcome: Added output-monitor and watchdog services, integrated them into runtime/plan orchestration/hook dispatch, and added integration coverage proving anti-thrash behavior and auditable watchdog retries.

Key code changes
- Added `server/src/services/orchestration/outputMonitor.ts`:
  - Computes normalized material hashes for runtime/plan output.
  - Persists per-task per-source monitor state in `tasks.metadata_json`.
  - Debounces high-frequency output changes and only reports material changes.
- Added `server/src/services/orchestration/watchdog.ts`:
  - Detects stale blocked nodes (`queued`/`awaiting_children`) and stale running nodes (`in_progress`/`waiting_input`).
  - Enqueues idempotent/safe orchestration jobs (`task_queue_dispatch` and `plan_orchestration_pass`).
  - Emits auditable `orchestration.watchdog.action.enqueued` events.
- Updated `server/src/services/orchestration/hooks.ts`:
  - Extended `on_node_output_updated` idempotency keying to include output hash/source.
  - Added `task.output.material_changed` mapping to `on_node_output_updated`.
- Updated `server/src/services/runtime.ts`:
  - Monitors captured session output through `observeNodeOutputMaterialChange`.
  - Emits `task.output.material_changed` only when material output changes occur.
- Updated `server/src/services/planOrchestrator.ts`:
  - Monitors plan file material changes and emits `task.output.material_changed` for plan output updates.
  - Runs watchdog on timer-tick-triggered plan orchestration passes.
- Updated `server/src/services/runtimeWorker.ts`:
  - Runs watchdog after runtime start/input worker actions (when project context is known).
- Updated `server/src/integration.test.ts`:
  - Added test: non-material output changes do not thrash orchestration.
  - Added test: watchdog enqueues stale-node readiness/re-review actions with event audit trail.

Tests/validation performed
- Required CLI check from `/server`: `npm run cli -- --help` (passed).
- TypeScript build from `/server`: `npm run build` (passed).
- Integration tests from `/server`: `npm test` (passed: 36 tests, 0 failures).
- New orchestration tests passed:
  - non-material output anti-thrash behavior
  - watchdog stale-node enqueue and event auditability

Remaining risks or follow-ups
- Output monitor state currently lives in `tasks.metadata_json`; long-term shape/versioning policy for this sub-structure should be documented.
- Watchdog stale thresholds are fixed constants and may need tuning under real workload patterns.
- Watchdog currently enqueues broad orchestration jobs (safe/idempotent), but future optimization could target finer-grained readiness/review handlers if introduced.
- Events retention growth still applies (especially with watchdog audit events); pruning/archival strategy may be needed at scale.
