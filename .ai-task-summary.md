# Task Summary

## Goal and Outcome
- Goal: Establish a baseline implementation plan for hierarchical orchestration over existing plan/task primitives, define prompt artifact naming/file conventions, and lock a strict prompt IO contract for runtime coordinators.
- Outcome: Added architecture and prompt-contract documentation plus a new `/prompts` artifact directory with shared IO requirements and runtime template files, all mapped to existing services/tables without introducing new storage primitives.

## Key Code Changes
- Added architecture baseline doc:
  - `docs/architecture/hierarchical-orchestration.md`
  - Defines `Epoch -> Phase -> Plan -> Task -> Exec` as metadata conventions over current runtime primitives.
  - Includes canonical node metadata contract (tier, parent/children, dependencies, status, idempotency, merge settings, iteration budget, evidence).
  - Maps abstraction to existing storage/services (`tasks`, `plan_revisions`, `plan_revision_items`, `task_sessions`, `plan_orchestration_state`; `planParser`, `planOrchestrator`, `cliServices`).
  - Links to `/prompts` artifacts.

- Added strict prompt IO contract doc:
  - `docs/architecture/prompt-contract.md`
  - Requires dual output shape: natural-language rationale + structured JSON/YAML payload.
  - Defines required schema fields including goals, non-goals, DoD, deps, artifacts, risks, idempotency, bounded iteration, auto-merge guidance.
  - Documents where contract is validated/consumed (`planParser`, `cliServices extract/approve`, `planOrchestrator`).

- Added prompt artifact directory and templates:
  - `prompts/README.md`
  - `prompts/shared-input-output.md`
  - `prompts/plan-generate.md`
  - `prompts/plan-extract.md`
  - `prompts/plan-approve.md`
  - `prompts/task-execution.md`
  - Establishes one markdown file per runtime template and shared required input/output sections.

- Risk: Epoch/Phase are metadata conventions only; no first-class querying/reporting model yet.
- Follow-up: Add runtime validation utilities (schema checks) and wire them into extract/approve boundaries.
- Follow-up: Add integration tests that fail on missing required structured fields in coordinator outputs.
- Follow-up: Optionally add examples of valid/invalid payloads in `prompt-contract.md` for faster adoption.
