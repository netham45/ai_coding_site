# Task Summary

## Goal and outcome
- Goal: refactor runtime-state services (`events`, queue/runtime helpers, terminal/IDE task session persistence) so project-scoped runtime records are read/written from the owning project DB, while app DB remains the source for project discovery and membership context.
- Outcome: completed. Runtime lifecycle, queue dispatch, terminal gateway session persistence, and IDE heartbeat-failure persistence now operate against project DB handles for project-scoped tables.

## Key code changes
- Updated `server/src/services/runtime.ts`:
  - Added project-aware runtime context (`RuntimeTaskContext`) and task-to-project DB resolution.
  - Refactored task/session/dependency/transition/merge/event operations to use `projectDb` instead of app DB.
  - Updated `startTaskRuntime(...)` and `sendTaskRuntimeInput(...)` to accept optional project context.
  - Updated auto-merge, recovery, and heartbeat loops to iterate project DBs and monitor project-local active sessions.
  - Ensured runtime-originated `recordEvent(...)` calls pass `database: projectDb`.
- Updated `server/src/services/queue.ts`:
  - Reworked queued-task scan to iterate projects from app DB, query queued tasks in each project DB, and dispatch `startTaskRuntime(...)` with project context.
- Updated `server/src/ws/terminalGateway.ts`:
  - Added project-scoped task resolution for authenticated users (app DB membership -> project DB task lookup).
  - Moved terminal task/session status reads and `task_sessions` heartbeat/output writes to the owning project DB.
  - Updated terminal attach/detach event writes to include `projectId` and `database: projectDb`.
- Updated `server/src/index.ts`:
  - Changed `startIdeHeartbeat(...)` failure callback to update `ide_instances` in project DBs instead of app DB.
- Updated route call sites:
  - `server/src/routes/tasks.ts` now passes project context for runtime start/input calls.
  - `server/src/routes/plans.ts` now passes project context when sending plan regeneration runtime input.

## Tests/validation performed
- Ran `npm run build -w server`.
- Result: TypeScript compilation succeeded with no errors.

## Remaining risks or follow-ups
- Runtime/queue/heartbeat now discover work by iterating all projects and opening project DB handles each pass; functionally correct but may need optimization for large project counts.
- No new automated tests were added for cross-project runtime behavior, terminal gateway project resolution, or project DB unavailable/corrupt runtime paths.
- Runtime project-context fallback (task lookup across accessible project DBs when context is not passed) is intentionally retained; this may have performance impact and could be tightened by always requiring explicit context from call sites.
