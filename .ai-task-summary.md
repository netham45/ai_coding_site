## Goal and outcome
- Goal: make auto-merge default behavior explicit and controllable from the UI at each node tier, with visible and consistent automation state across project tree and detail views.
- Outcome: node creation now defaults merge automation to ON (unless explicitly disabled), automation state is shown in both tree rows and detail panels, and server-side defaults enforce the same behavior when clients omit flags.

## Key code changes
- `web/src/components/NodeCreateForm.tsx`
  - Changed create-form defaults to `autoMerge: true`.
  - Added plan-tier `autoMergeOnComplete` control with default `true`.
  - Updated payload submission to send:
    - `autoMerge` for all tiers.
    - `autoMergeOnComplete` for non-task tiers.
  - Kept disablement as explicit user action via visible checkboxes.
- `web/src/pages/ProjectDetailPage.tsx`
  - Extended `onCreateNode` payload typing to include `autoMergeOnComplete`.
- `web/src/components/OrchestrationTree.tsx`
  - Added badges in each node row for:
    - `auto-merge: on|off`
    - `auto-merge on complete: on|off` (plan nodes)
- `web/src/pages/TaskDetailPage.tsx`
  - Added task header badges for `autoMerge` and `autoMergeOnComplete` (plan mode).
- `web/src/components/NodeActionsPanel.tsx`
  - Added automation state badges so node detail panel explicitly shows current merge automation state.
- `server/src/routes/tasks.ts`
  - Updated `createProjectNode(...)` defaults:
    - `autoMerge` defaults to `true` when omitted.
    - `autoMergeOnComplete` defaults to `true` for plan-mode nodes when omitted.
  - This applies to unified `/nodes` and legacy wrappers routed through shared creation.
- `server/src/routes/plans.ts`
  - In legacy `/projects/:projectId/plans`, passed `autoMergeOnComplete: input.autoMergeOnComplete ?? true` explicitly into shared node creation.

## Remaining risks or follow-ups
- The create form now exposes plan-tier merge automation controls in both task and plan creation tabs (because Node Tier is switchable in one shared form). If product wants stricter per-tab control visibility, that should be narrowed by preset context.
- Tree/detail views now show automation flags, but there is no dedicated filtering/sorting by automation state yet.
- Existing nodes created before this change keep their stored automation values; defaults only affect newly created nodes.
