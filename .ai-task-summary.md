# Task Summary

## Goal and outcome
Goal: Implement the app-vs-project SQLite ownership split according to `docs/adr-sqlite-persistence-split.md`, including explicit invariants and moving project-local entities out of `data/app.sqlite`.
Outcome: Completed. The code now enforces app/global ownership in `data/app.sqlite` and project-local ownership in per-project SQLite files at `<project.base_path>/.ai-coding/project.sqlite`.

## Key code changes
- Database schema split implemented in `server/src/db/migrations.ts`:
  - App DB schema now owns only: `users`, `user_settings`, `projects`, `project_members`.
  - Project DB schema owns: `tasks`, task dependency/session/transition tables, plan revision tables, `ide_instances`, `merge_records`, `events`, and new `project_config` + `project_metadata`.
- DB access layer refactor in `server/src/db/index.ts`:
  - Introduced `appDb` and project DB open/init/validation helpers.
  - Added project DB metadata validation (`project_id` match) and startup/migration setup.
  - Added explicit ownership invariants in code comments:
    - single source of truth per table,
    - no cross-file foreign keys,
    - cross-DB linkage by IDs only.
- Added ownership/context helper module `server/src/db/ownership.ts` for app/project/task context resolution.
- Route/service rewiring to correct DB ownership:
  - App DB for auth/settings/membership checks.
  - Project DB for task/plan/runtime/event/IDE/merge persistence.
  - Updated key modules: `routes/projects.ts`, `routes/tasks.ts`, `routes/plans.ts`, `services/runtime.ts`, `services/queue.ts`, `services/events.ts`, `ws/terminalGateway.ts`, `ws/ideProxyGateway.ts`, `index.ts`.
- Type updates in `server/src/types.ts`:
  - Added `AppProjectRow` and `ProjectConfigRow`, with hydrated `ProjectRow` for combined app+config view.
- README updated to document split ownership and invariants.

## Remaining risks or follow-ups
- Monolithic-to-split historical data migration is not included here; this change implements ownership/cutover behavior in code and schema.
- Some task lookups across projects are scan-based and may need optimization for larger project counts.
- Additional operator tooling for project DB repair/recovery paths (`PROJECT_DB_UNAVAILABLE` / `PROJECT_DB_CORRUPT`) would improve operational workflows.
